# 评测方法与指标定义

> 本文回答三件事：评测集怎么造、四个指标怎么判、数字从哪来。
> 实测结果与失败归因见 [eval/reports/eval_50x3.md](../eval/reports/eval_50x3.md)
> 与 README「未达标项与已知问题」。

## 1. 评测集：50 题，标注值全部由标准 SQL 连库实测写回

- 分层（SPEC §8.2）：单指标 15 / 同环比 10 / 下钻归因 12 / TopN 8 / 纠错脏题 5。
- 每题标注（`eval/dataset.yaml`）：问题、类型、`standard_sql`（裁判 SQL）、
  `expected`（value/extras/direction/tolerance）、`value_desc`、`expected_path`、`notes`。
- **评测纪律：期望值不手拍**。`eval/validate_dataset.py` 是 expected 的唯一写入口——
  标准 SQL 连真实 mock 库执行，结果按结果形态约定写回：
  - 标量题（single_metric/compare/dirty）：1 行，第 1 列 = value，其余列进 extras；
  - drilldown 单行 = 因子分解（主变化率 + 各因子进 extras）；
    多行 = 维度贡献 `(dim, cur, prev, delta, share)` 按 |delta| 降序；
  - topn：多行按名次 `(dim, metric[, share])`，extras 附 top1 摘要。
- 相对时间以数据末日 2026-09-13 为「今天」（数据仅一年，同比不可出题，
  compare 层由月环比 + 周对周构成）。
- 脏题（dirty）：5 题带口径陷阱（退款口径/客单价分母/超范围品类/时间边界/无解题），
  `expected_outcome=unanswerable` 的无解题判「不编造完整回答」而非数值。
- `uv run python -m eval.validate_dataset --check` 连库复核 50/50 通过
  （orders=104,209，静态 mock 库）。

## 2. 四个指标的判定口径（eval/runner.py，判定全部是纯函数）

### 执行正确率（目标 ≥80%，实测 76% ❌）

证据 SQL 逐条用只读连接**重放**（不是信任 Agent 的自报），任一条结果与 expected
一致即过（`judge_execution` → `sql_result_matches`，相对误差 ≤ tolerance，默认 ±2%）：

- 标量：首行任一数值格 ≈ value；
- compare 回退：主变化率未直接出现时，两格分别 ≈ extras.cur/prev 则反推再比；
- drilldown 单行：value 命中后各因子（extras）也都须命中；
- drilldown 多行：按 dim 查行（顺序不敏感），每行 delta 命中，share 有值也须命中；
- topn：dim 名次序列全匹配，每行 metric/share 须命中；
- 率类（|expected| < 10）兼容百分比尺度（0.087 ↔ 8.7）；大数值不回退，防 53↔5300 误配。

### 结论正确率（目标 ≥70%，实测 70% ✅ 压线）

结论文本提取数值词元（`extract_numbers`：%/个百分点/pp ÷100、万/亿放大、千分位与
Unicode 负号归一；率类含取反候选——「下滑 8.7%」即 -0.087，符号由方向词承载），
主数值容差内命中且方向一致（`judge_conclusion` + `classify_direction`：
恰好一组方向词用词判，两组同现或无词用数值符号）。多行题要求各 dim 按序出现且
metric 命中；drilldown 另要求总变化与因子全命中。`failed` 直接判不过。

### 纠错成功率（目标 ≥50%，实测 0% ❌，结构性零分）

分母 = 5 道脏题。分子 = 「首轮 SQL 失败 ∧ 最终 answered ∧ 执行正确」的题。
首轮失败看 `steps_log` 首条 outcome ∈ {error, invalid, duplicate, empty, no_sql}
（`first_round_failed`，与 trace.jsonl 的 sql_result 事件同源同判）。
实测 4/5 脏题首轮直接对（没有失败可纠）、dt003 题级多数决 1/3 判否、dt005 无解题
按口径不进分子——0/5 是指标设计与题难度的结构性结果，不是 Reflexion 失效
（全量 150 次中 42 次首轮失败、13 次自修正后answered且执行正确）。

### 采样一致性（目标 ≥80%，实测 92% ✅）

同题独立跑 3 次，每次取结论签名（关键数值 = 与 expected 最近的词元换算到同量级，
方向 = 方向词/符号），存在 ≥2 个签名两两一致（数值相对差 ≤5%、方向相同）即过
（`consistent`）。**稳定地错也算一致**——一致性 ≠ 正确性。

## 3. 题级聚合与运行

- 聚合：exec/conclusion/recovery 取采样的**严格多数**（2·命中 > 采样数；平票判否，
  `majority`）；
- 运行：`uv run python -m eval.runner --samples 3`（全量 50×3 ≈ 2 小时；
  `--type/--id/--limit` 取子集）；评测 trace 独立落 `runs/eval/`、checkpoint 独立
  `eval-checkpoints.db`；
- 报告：`eval/report.py` 渲染 markdown（总体/分层/失败题明细/token 消耗）+ 同名
  `.json` 附完整 run 级结构。入库报告 `eval/reports/eval_50x3.{md,json}` 即
  2026-09-16 全量实测（模型 glm-5.3，150 次分析，7990s），README 评测表与其逐格对账。

## 4. mock 库与数值自洽（评测的地基）

- 生成器 `data/mock_gen.py`（种子 20260915，drop+recreate 一键复现）：
  以「日 × 类目 × 渠道」为控制单元，先采 UV、再按转化率生成 paid 订单量、
  最后展开明细金额——「流量跌」「转化跌」两个故事在数值上天然自洽；
- `self_check()` 是裁判 SQL 集，SPEC §5.3 三个植入故事的定稿数值
  （面部精华 -25.4%、618 复购 +6.97pp、Top1 雪滢 12.35%）全部由它连库实测；
- 指标口径唯一源 = SPEC §5.2 指标字典，`metrics.py` 模板与 `dataset.yaml`
  标准 SQL 都服从它（GMV = 明细求和、status ∈ {paid,shipped,completed}、
  时间锚 paid_at、左闭右开、复购 = 首单后 30 天内第二单）。

## 5. 为什么这套评测是可信的（防「自说自话」设计）

1. 裁判 SQL 与 Agent SQL 都在同一静态库上跑，数值可比；
2. 执行正确率靠**重放**不靠自报；
3. 期望值唯一写入口是连库校验器，人手不碰数值；
4. 指标判定是纯函数，判定口径用合成数据单测钉死（tests/test_runner.py 21 条）；
5. 未达标项原样呈现并归因（不 hack 指标凑数，留 v2 决策）。
